# US004 evidence - Create the canonical synthetic fixture corpus

Status: IN_PROGRESS

## Blueprint target
US004 requires at least 40 small synthetic JSON fixtures containing ID, category, HTML, literal expected Markdown and literal expected text, with status where applicable. Required coverage includes blocks, inline marks, URLs, code, tables, whitespace, entities and removed content. The hand-reviewed set must include nesting, adjacent block boundaries, Unicode, unsafe targets and malformed HTML. Missing expected fields and duplicate IDs must fail validation. Large boundary cases must be generated by scripts instead of committed as megabyte-scale fixtures.

## Implementation checkpoint
- `tests/fixtures/corpus.json`: 62 synthetic records. Expected outputs are literal reviewed strings; they are not produced by the converter.
- `scripts/validate-fixtures.mjs`: schema/provenance/coverage/duplicate-ID validator with category and review-tag reporting.
- `scripts/validate-fixtures.test.mjs`: negative tests for a missing expected field, duplicate ID and prohibited external provenance metadata.
- `scripts/generate-boundary-fixtures.mjs`: in-memory exact/plus-one generators for the decoded-HTML and raw-body byte ceilings; no megabyte fixture is committed.
- `package.json`: `test:fixtures` is part of `verify:current`.

## Provenance
Every fixture was authored for this blueprint using synthetic strings and reserved/example-style URLs. No customer payload, private dataset or scraped third-party document is present.
