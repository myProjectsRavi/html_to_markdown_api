# US005 evidence - Implement exact routing and response headers

Status: IN_PROGRESS

## Blueprint acceptance target
US005 requires exact case-sensitive paths and methods, JSON 404/405 envelopes, route-specific Allow headers, a public health response, and centrally applied `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, and JSON content type. Wrong case and trailing slash must be 404. HEAD and OPTIONS on known paths must be 405. Query values must not appear in response bodies or logs. Conversion routes may use a typed internal placeholder but must not fabricate success.

## Implementation checkpoint
This checkpoint:
- replaces the US002 bootstrap-only handler with an exact manual router in `src/index.ts`;
- adds `src/http/response.ts` for central JSON/security headers and fixed error envelopes;
- adds thin health and conversion route modules;
- returns exact `{"status":"ok"}` for `GET /health`;
- returns fixed 404 and 405 envelopes, including `Allow: GET` or `Allow: POST` on known-path method failures;
- returns a controlled 503 placeholder for valid conversion POST routes until later authentication/body/conversion stories are integrated;
- adds a workerd table-driven route/method/header suite and query non-echo checks;
- updates the bootstrap test to exercise the public health route.

The production routing code contains no logging call; query strings are used only by the URL parser to obtain `pathname`, and test assertions ensure query values are absent from response bodies.
