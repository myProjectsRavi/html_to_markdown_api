# US006 evidence - Authenticate RapidAPI origin requests

Status: IN_PROGRESS

## Blueprint acceptance target
US006 requires conversion routes to authenticate with `RAPIDAPI_PROXY_SECRET` before consuming the body. Missing/incorrect/prefix-only/suffix-only/oversized/duplicate-or-coalesced credentials must fail with 403; missing server configuration must return 503; the exact secret must proceed; health remains public. A customer `X-RapidAPI-Key` is not trusted as origin authentication. Evidence requires auth integration tests, a body-read spy, and log review for both fake and configured secret patterns.

## Recovery finding
A watchdog acquired US006 and committed `src/auth/rapidapi.ts` at `fd9b1e873a12dc90d314ab6f8e085f0f586fe940`, and generic CI passed. However, the module was not wired into `src/index.ts`, no US006 acceptance test existed, BACKLOG still said TODO, STATE still described US005, and the lock was left active until its lease expired. Therefore that green CI was not treated as US006 completion evidence.

## Recovery implementation
This checkpoint:
- integrates authentication only after exact path/method routing and before conversion/body work;
- keeps `GET /health` independent of auth configuration;
- caps supplied proxy credentials at 512 characters and rejects coalesced comma-containing values;
- validates the configured secret before business requests proceed;
- compares SHA-256 digests with a full fixed-length byte scan, while explicitly making no constant-time guarantee;
- adds Worker-runtime tests for the full acceptance matrix, customer-key-only rejection, body non-consumption, and absence of secret material from console capture.
