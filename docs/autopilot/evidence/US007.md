# US007 evidence - Read request bodies within a hard bound

Status: IN_PROGRESS

## Source-derived target
US007 requires Content-Type and Content-Encoding validation, Content-Length early rejection, counted ReadableStream consumption, cancellation after actual bytes exceed 800000, and strict UTF-8 decoding only after bounded collection. Exactly 800000 raw bytes must be admitted to the next JSON-validation stage; 800001 must be 413 even when Content-Length is absent or false. Unsupported media/encodings are 415, invalid UTF-8 and malformed/disconnected bodies map to fixed 400 errors, and overflow must cancel the reader.

## Implementation checkpoint
- `src/http/body.ts` does not call `request.text()` or `request.json()`; it obtains a reader from the request body and counts every chunk.
- Oversized chunks are rejected before copying/retaining them.
- Retained chunk backing buffers are copied only after the cap check; total retained raw chunk bytes cannot exceed 800000.
- Numeric Content-Length greater than the cap is rejected early, while missing, false-small, or malformed values never bypass actual stream counting.
- Strict `TextDecoder("utf-8", { fatal: true })` runs after collection.
- `src/index.ts` invokes the body gate only after route/method resolution and successful US006 authentication.
- `tests/body.test.ts` covers exact/+1 boundaries, oversized chunks, false/missing Content-Length, media/encoding, one-byte split emoji, invalid UTF-8, early disconnect, overflow cancellation, and body-log capture.
- US006 accepted-secret integration requests now carry the JSON media type required by the subsequent US007 stage.
