# US008 evidence - Validate JSON and decoded HTML precisely

Status: IN_PROGRESS

## Source-derived acceptance target
Parse only the already bounded/strictly decoded body from US007. Require an object containing only a string `html`. Reject null/arrays/non-string values/extra fields and unpaired UTF-16 surrogates. Missing `html` maps to `missing_html`. Measure decoded HTML with TextEncoder before normalization. Empty and whitespace-only HTML remain valid at this layer. Exactly 131072 decoded UTF-8 bytes pass; plus one fails. Native JSON duplicate-key behavior is documented as last value wins; no second JSON parser is introduced.

## Implementation checkpoint
- `src/http/request.ts` performs native JSON parsing, exact request-shape validation, surrogate validation and decoded UTF-8 byte counting.
- `src/index.ts` places US008 after route/method, server config/auth and US007 bounded/strict body handling, matching the frozen precedence.
- `tests/request.test.ts` covers malformed JSON, missing/invalid fields, empty/whitespace HTML, ASCII and multibyte byte boundaries, escaped JSON counting, emoji/combining marks, surrogate validity, duplicate-key behavior and Worker integration.
- US007's existing raw-body exact/plus-one tests remain part of `verify:current`, so raw-body and decoded-HTML ceilings are exercised independently.
