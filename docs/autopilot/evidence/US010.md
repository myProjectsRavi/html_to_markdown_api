## Retention and skipped-subtree reasoning
`src/html/parse.ts` maintains an explicit frame stack, never a recursive application traversal. A retained element is created only after its attributes have passed validation. Each retained element, text node, comment, or processing instruction consumes the retained-node budget.

For configured skipped elements, frames carry `node: null`. Descendants are not added to the application tree, but their open/text/close/attribute callbacks still call the same budget. A targeted template fixture with a reduced event ceiling proves a discarded nested subtree can trigger the event limit; the limit observer fires exactly once.

US007 bounds raw JSON and US008 bounds decoded HTML to 131072 UTF-8 bytes before this parser is called. Combined with depth/node/attribute limits, a long malformed tag cannot create an unbounded retained application structure. The adversarial unterminated-tag test with a 257-scalar attribute name terminates with a typed limit before an application element is retained.

## Parser stop and error evidence
A `ParserLimitError` thrown from a callback unwinds `parser.end()`; no parse tree is returned. The parser integration test spies on the limit observer and verifies one stop notification. The Worker catches limit failures and returns the fixed `input_too_complex` error. Other parser exceptions are normalized to `ParserInternalError` and map to `internal_error`; internal exception text is not exposed.

There is deliberately no timer and no `Promise.race`. Synchronous parser CPU is bounded structurally, not by pretending application JavaScript can preempt itself.
