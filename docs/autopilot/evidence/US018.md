## Acceptance evidence

The renderer selects a fenced-code delimiter at least three backticks long and always one longer than the longest contained backtick run. It normalizes protected CRLF/CR to LF through the shared text stage, preserves tabs and internal/terminal blank lines, and adds a single synthetic LF before the closing fence only when source code lacks a final newline. Tests cover blank first/last lines, no-final-newline input, embedded triple backticks, empty blocks, tabs, approved `language-...` child-code classes, malicious class rejection, list/blockquote composition, and an exact output-scalar boundary.

The independent test fence parser documents the Markdown renderer distinction: a source code block without a terminal newline serializes with a required separator before the closing fence, so downstream Markdown parsing observes the normal terminal code-block LF rather than a byte-identical source round trip.
