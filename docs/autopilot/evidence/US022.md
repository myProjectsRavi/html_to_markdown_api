## Acceptance evidence

The renderer emits GFM tables only for rectangular, non-nested shapes with no effective rowspan/colspan. Rows are collected across direct `tr` children and `thead`, `tbody`, and `tfoot` in source order. An all-`th` first row is the header; otherwise an empty header is inserted and every source row remains data, so a headerless first row is never lost.

Exact fixtures cover an all-`th` header, headerless data, empty cells, a one-cell table, explicit table sections, escaped embedded pipes, Telugu and Arabic Unicode, and ignored inline formatting while preserving cell text. A test-only GFM structural parser independently verifies output column and data-row counts.

The configured table limits are exercised through the real HTML → parser → clean tree → Markdown pipeline: 200 rows, 32 cells per row, and 6,400 total cells pass at their exact boundaries; one row, one column, and one total cell beyond the respective limits are rejected. The first boundary attempt in run `37136582405` used text in all 6,400 cells and correctly hit the earlier parser `retainedNodes` safety ceiling before the table writer. The repaired fixtures use empty cells so parser safety no longer preempts the table-limit boundary being tested; production table code was unchanged by that repair.

Header and shape policy is documented in `docs/decisions/markdown-tables.md`. Complex-table fallback remains explicitly reserved for US023; US022 does not emit raw table HTML.
