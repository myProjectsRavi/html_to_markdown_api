## Corpus and acceptance

Generator `us033-corpus-v1` measures plain, entity-heavy, link-heavy, bounded nested, tabular and malformed-but-parseable HTML at approximately 1, 16, 64 and 128 KiB. Both `/v1/html/markdown` and `/v1/html/text` are measured end-to-end, with separate stage timing for JSON validation, parser, clean/normalize, Markdown serialization and clean-text serialization.

The ordinary 128 KiB fixture is accepted with HTTP 200 by both endpoints. Link, nested and table 128 KiB fixtures also remain accepted. Entity-heavy and malformed 128 KiB fixtures reject with HTTP 422 because their tokenizer/event complexity exceeds the independently enforced parser budget; these are correctly labelled rejected and are not mixed into successful latency distributions.

The isolated 256 KiB experiment returns HTTP 413 on both endpoints in all three processes and remains outside accepted-path timing.

## Observed local/CI timing

The repeatable slowest supported cell is 128 KiB link-heavy Markdown:

- run 1: p50 15.1424 ms, p95/p99/max 16.6969 ms
- run 2: p50 15.1868 ms, p95/p99/max 17.1757 ms
- run 3: p50 15.3049 ms, p95/p99/max 16.7327 ms

The dominant stage is Markdown serialization for the same link-heavy 128 KiB cell, with p95 values 10.1429, 10.2277 and 10.0969 ms. Link-heavy 64 KiB Markdown is the next consistent hotspot.

One run-3 1 KiB Markdown sample reached 11.7789 ms while its p50 remained 0.5949 ms and the same cell stayed near 0.6 ms median in the other processes. Because the spike does not scale with input size and is absent from the repeat runs, it is recorded as host scheduling/wall-clock noise, not production CPU evidence.
