# US034 - Remove measured performance bottlenecks

Status: DONE

Tested code SHA: `5b0c5bdd1fda6c7c667aa6ee8149638abc214db8`

## Profile target

US033 identified link-heavy Markdown as the stable supported-path hotspot. At 128 KiB, Markdown serialization p95 was 10.1429 / 10.2277 / 10.0969 ms across three independent processes, while end-to-end p95 was 16.6969 / 17.1757 / 16.7327 ms.

Inspection found repeated allocation work inside the hot link path:

- regex plus substring allocation for every existing percent triplet in destination serialization;
- regex testing for every safe ASCII destination character;
- a newly constructed HTTP/HTTPS prefix RegExp for every classified absolute URL;
- TextEncoder allocation/work even for fully ASCII URLs that can be byte-counted directly.

No cross-request cache was introduced.

## Optimization

- Replaced per-character destination regex checks with char-code predicates.
- Replaced percent-triplet substring/regex validation with direct code-unit checks.
- Replaced dynamically constructed HTTP prefix RegExp with a fixed prefix comparison.
- Added an ASCII fast path for URL byte-limit checks while retaining TextEncoder measurement for non-ASCII input.
- Kept all URL safety decisions, parser/output limits and the 128 KiB release configuration unchanged.
